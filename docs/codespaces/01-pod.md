このハンズオンでは、Kubernetesにアプリをデプロイして、わざと**こわして**みます。

| シナリオ | こわすもの |

## 進め方

- 右側の黒い画面が**ターミナル**です。ここでコマンドを実行します
- コマンドは**クリックするだけ**でターミナルで実行されます。自分で入力する必要はありません
- 各ステップの最後にある「Check」ボタンを押すと、できているかを確認できます
- 困ったら `ヒント` を開いてみてください。それでもわからなければ、手を挙げて呼んでください

## Podを作る

**Pod**（ポッド）は、Kubernetesでコンテナを動かすときの一番小さな単位です。まずはPodを1つだけ作ってみましょう。

### やること

まずは環境に何もないことを確認しましょう。

```
kubectl get pods
```

次に配布済みのYAMLファイルを使って、Podを作ります。

```
kubectl apply -f ~/manifests/01-pod/pod.yaml
```

Podの状態を見てみましょう。

```
kubectl get pods
```

### 観察する

`STATUS` が `Running` になるまで、何回か `kubectl get pods` を実行してみてください。

<details><summary>ヒント</summary>

`ContainerCreating` と表示されているあいだは、コンテナを準備中です。少し待ってからもう一度実行してみましょう。

</details>

`Running` になったら「Check」を押して次に進みましょう。

> **確認**：次のコマンドを実行してください。
>
> ```
> check 01-pod 1
> ```

## Podを消す

作ったPodを、わざと**消して**みます。

### やること

```
kubectl delete pod hello-pod
```

### 観察する

もう一度、Podの状態を見てみましょう。

```
kubectl get pods
```

少し待ってから、もう一度実行してみてください。Podはどうなりましたか？

<details><summary>ヒント</summary>

`No resources found in default namespace.` と表示されていれば、Podがひとつもない状態です。

Podがいなくなったまま、戻ってきません。大変です。壊れてしまいました。

</details>

確認できたら「Check」を押しましょう。

> **確認**：次のコマンドを実行してください。
>
> ```
> check 01-pod 2
> ```

## Podを復活させる

Podは自分では戻ってきません。**人間が**もう一度作ってあげましょう。

### やること

最初と同じYAMLファイルを、もう一度applyします。

```
kubectl apply -f ~/manifests/01-pod/pod.yaml
```

### 観察する

Podの状態を見てみましょう。

```
kubectl get pods
```

`STATUS` が `Running` になるまで、何回か実行してみてください。

<details><summary>ヒント</summary>

`kubectl apply -f` は「ファイルに書いた状態にしてほしい」とお願いするコマンドです。Podがない状態でapplyしたので、もう一度作られました。

</details>

### なぜ？

Podが消えても、誰も気づいてくれません。復活させるには、人間が気づいて、もう一度作るしかありません。

`Running` になったら「Check」を押しましょう。

> **確認**：次のコマンドを実行してください。
>
> ```
> check 01-pod 3
> ```

## ふりかえり：誰が直した？

| こわしたもの | どうなった？ | 誰が直した？ |
|---|---|---|
| ① Pod | 消えたまま戻らなかった。人間がもう一度作るしかなかった | **誰も直さない** |

PodはコンテナをKubernetesクラスタで起動するための最小単位のリソースです。

Podは非常にシンプルな作りですが、消えたらReconciliation Loopが働いていても消えたままです。
